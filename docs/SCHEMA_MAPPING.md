# Source → Schema Mapping

How the scraper's Excel exports map onto the frozen schemas. Generated by
`backend/map_sources.py`. Real/final data isn't loaded yet and the media→text
step hasn't run, so text fields are placeholders that Stage 1 fills.

---

## `Single Creator.xlsx` → `corpus.json` (voice axis)

15 rows, creator `ChaosAdam13`, all YouTube Shorts.

| Excel column | → corpus field | transform |
|---|---|---|
| `creator` | `creator.handle` | first row |
| — | `creator.niche` | **not in source — set manually** (e.g. "German food/comedy shorts") |
| `creator_url` / `video_url` | `creator.platforms` | derived → `["youtube"]` |
| `video_id` | `items[].id` | as-is |
| `content_type` (`short`) | `items[].platform` = `youtube`, `media_type` = `video` | shorts are videos we transcribe |
| `title` | `items[].title` | as-is (hashtag-stuffed; not the voice signal) |
| `video_url` | `items[].media_url` | **fed to Wizper** → fills `transcript` |
| — | `items[].transcript` | **null now** → Wizper (speech→text) at Stage 1 |
| `description` | `items[].caption` | mostly empty (2/15) |
| — | `items[].hook` | **null now** → derived from transcript at ingest |
| `published_at` | `items[].published_at` | ISO8601 |
| `views` | `items[].metrics.views` | int |
| `likes` | `items[].metrics.likes` | int |
| — | `items[].metrics.comments` | **not scraped → 0** |
| — | `items[].performance_percentile` | **0.0 now** → computed at ingest (engagement rank) |
| `rating` | — | dropped (all 5.00, no signal) |
| `channel_id`, `position`, `updated_at`, `thumbnail`, `scraped_at` | — | not needed for fingerprint |

**Note:** `transcript` is the whole voice signal and is currently null for all 15 — titles alone give a garbage fingerprint. The Wizper pass is mandatory, not optional.

## `Trends.xlsx` → `trends.json` (trend axis)

120 rows from Bluesky (65) + Mastodon (55), global. Raw trend rows map to
*proto* `trend_cards`; Stage 3's LLM later abstracts several rows into
higher-level `pattern`s.

| Excel column | → trends field | transform |
|---|---|---|
| `scraped_at` | `built_at` | max across rows |
| — | `niche` | **not in source — set manually** |
| `trend_key` | `trend_cards[].id` | as-is |
| `title` | `trend_cards[].pattern` | post text / topic / hashtag |
| `title` + `context` + `url` | `trend_cards[].evidence` | array, nulls dropped |
| `platform` | `trend_cards[].observed_on` | array |
| `category` | `trend_cards[].estimated_decay` | mapped (hashtag/topic/post/whats_hot → `days`, else `weeks`) |
| `metric_value` | `trend_cards[].confidence` | min-max normalised **within each `metric_name` group** (likes/boosts/topic_rank/uses_24h aren't comparable raw) |
| `category` | `trend_cards[].category` | kept for Stage 3 |
| `metric_name` + `metric_value` | `trend_cards[].metric` | kept for Stage 3 |
| `author`, `has_video`, `url`, `published_at` | same-named fields | kept for Stage 3 |
| `geo` (all `global`), `rank`, `video_thumbnail` | — | not used |

## Open items (manual / not implemented)

1. **`niche` is blank in both** — no source column. Set it manually (used to focus the trend axis).
2. **Domain gap:** creator = German YouTube food/comedy shorts; trends = English Bluesky/Mastodon general-interest. Trend-alignment on this exact pairing will read low. For the demo's tension moment, trends ideally come from the creator's own niche/platform. Data-sourcing decision — flagged, not changed.
3. **Sheet-contract vs. Excel:** the n8n workflow reads a Google Sheet with columns `id, platform, media_type, media_url, author, …`. This Excel uses `video_url`/`content_type` and has no `media_type`/`author`. Either reshape the Excel to those columns before loading the sheet, or point the workflow's field expressions at the Excel's names. Not implemented.
